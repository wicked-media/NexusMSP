## Completion contract

A capability is **Production ready** only when its persistence, secured API, tenant and role enforcement, audit/event evidence, frontend states, automated tests, operating documentation, monitoring and production configuration are all verified. A route, card, demo response or navigation entry alone is not implementation evidence.

Status values: `Not started`, `Discovery required`, `Architecture required`, `In development`, `Partially implemented`, `Implemented`, `Testing`, `Production blocked`, `Production ready`, `Deferred`, `Rejected with reason`.

Priority values: `P0` release blocker, `P1` core pilot, `P2` subsequent release, `P3` roadmap.

## Release 1 blocking decisions

1. Tenant boundary evidence must cover authenticated users restricted to different clients, not only helper-level tests.
2. Authentication has distributed login throttling; session revocation/rotation design and the production SSO/passkey decision remain open.
3. Nexus Agent needs signed artifact and staged rollback proof on a pilot fleet.
4. External messaging, Microsoft, Xero, Yeastar, backup and remote providers require sandbox acceptance evidence.
5. Nexus data, uploads and installer artifacts require timed restore evidence.
6. Monitoring, alert destinations, owners and incident response are implemented in the production stack; deployed firing/resolved acknowledgement evidence remains mandatory.
7. All critical and high findings require closure plus independent penetration testing before broad rollout.

## Change control

Update this register in the same change that advances a capability. Evidence must be a test, code path, runbook, deployment record, screenshot or external acceptance record. Never use “screen exists” as evidence of completion.
