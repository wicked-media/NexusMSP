An applied migration's recorded description is part of its identity, so editing one is `drifted`; a row for a migration this release does not define is `unknown`; both make the database incompatible and are blocking, while `pending` is reported and is deliberately not fatal, because the previous release is still serving until the change window applies it. Auditing the event backbone found a concrete, reversible gap: `purge_expired_events` selects `platform_events` by `retention_until <= now` and sorts by that same field from the six-hourly retention loop, while `ensure_event_backbone_indexes` covered five other access paths on that collection and never this one, so every retention pass was a collection scan plus an in-memory sort over the platform's fastest-growing collection. `0002-index-platform-event-retention` creates that index, and its down path drops it, restoring the previous index set exactly.
